# SAUT — Reference Protocol

References are evidence for a design decision, not authority over the SAUT design system.

## Good references

Save a reference only when it teaches a concrete solution relevant to SAUT, such as:

- campaign composition;
- garment photography;
- product-detail hierarchy;
- product-grid rhythm;
- filter behavior;
- mobile commerce;
- customization ergonomics;
- typography hierarchy.

Every good reference must record:

- Source
- Problem
- Take
- Reject
- SAUT translation

Never copy another brand's palette, typography system, logo treatment or recognizable composition.

## Bad references

Use counterexamples to identify recurring failure modes:

- generic SaaS layout;
- cards for every section;
- bento by default;
- decorative glassmorphism;
- arbitrary gradients/glows;
- inaccessible contrast;
- product images made secondary to chrome;
- desktop merely squeezed into mobile;
- marketing copy that could belong to any brand.

## Change-the-logo test

If replacing the SAUT logo with an unrelated company still makes the screen feel equally plausible, the design is insufficiently specific.

## Folder usage

- `docs/references/good/` contains approved visual references plus annotations.
- `docs/references/bad/` contains counterexamples plus the failure being illustrated.

Unannotated image dumps do not count as design guidance.
